## 一、留言系统正式退役

本次更新正式移除了主站自建的留言系统，包括独立留言页面、导航入口、主页留言预览、相关 JavaScript 脚本、专用 CSS 样式、图片资源，以及留言数据统计与同步任务。

此次调整不保留备用留言模块，也不接入第三方替代服务。

留言系统曾是网站的重要交互功能，但随着网站逐渐向个人知识库与内容展示平台发展，维护独立留言功能的实际价值已不足以覆盖其持续维护成本。移除该模块能够减少代码复杂度、降低维护负担，让网站更加专注于数学笔记、个人记录和内容展示。

此前介绍留言系统的文章与历史更新摘要继续保留，作为网站发展过程的一部分，不对历史记录进行追溯性删除。

## 二、主页布局与统计模块优化

在移除留言功能的同时，对主页布局进行了相应调整。

主页前两行保留原有顺序，第三行改为由「更新公告」与「关于我」两个模块各占半行，使桌面端布局更加紧凑、均衡。

移动端则恢复明确的单列排列方式，避免两个模块因屏幕宽度不足而造成拥挤。

站点统计卡同步调整：

- 移除原有的「留言」统计项。
- 新增「画廊」统计项，直接读取现有画廊数据，显示真实图片数量。
- 保留笔记、追番等原有统计内容。
- 建站天数继续独立显示，不受其他统计模块调整影响。

此次改动减少了已经退役的功能入口，并进一步统一主页的信息展示方式。

## 三、网站 DNS 与托管平台迁移

本次更新的另一项重要工作，是将网站的基础设施迁移至 Cloudflare。

此前网站使用阿里云提供的 DNS 解析服务，并通过 GitHub Pages 发布静态网页。随着网站内容逐渐增加，为简化部署流程、集中管理域名并使用更完善的边缘网络服务，决定将 DNS 与网站托管统一迁移到 Cloudflare。

### 1. DNS 托管迁移

首先在 Cloudflare 添加根域名 `yang181969.com`，随后于阿里云域名管理后台，将原有的阿里云 DNS 服务器替换为 Cloudflare 分配的名称服务器。

迁移完成后，阿里云继续作为域名注册商，Cloudflare 则负责域名解析与流量代理。

同时将原有的 `www.yang181969.com` 和 `work.yang181969.com` 子域名迁入 Cloudflare DNS 管理。

### 2. 主站迁移至 Cloudflare Pages

将 GitHub 仓库 `yang181969-ship-it/yang283643` 连接至 Cloudflare Pages，建立对应的 Pages 项目，并使用 `main` 分支进行生产环境部署。

完成后，将根域名 `yang181969.com` 绑定至 Pages 项目，启用 HTTPS，并验证生产环境部署状态。

网站源码与版本历史继续保留在 GitHub，Cloudflare 负责自动获取代码并部署网站。

### 3. Work 子站迁移

随后对独立仓库 `yang181969-ship-it/work` 执行相同的迁移操作。

新建独立的 Cloudflare Pages 项目，将 `work.yang181969.com` 绑定至对应部署地址，并完成 SSL 证书配置。

主站和 Work 子站保持独立的 GitHub 仓库、Pages 项目及部署流程，避免不同项目之间相互影响。

### 4. DNS 记录整理

随着两个网站均完成迁移，删除原来指向 GitHub Pages 的旧解析记录，改用 Cloudflare Pages 对应的 CNAME 记录。

最终保留三条主要 DNS 记录：

| 域名 | 解析目标 |
|---|---|
| yang181969.com | yang283643.pages.dev |
| www.yang181969.com | yang283643.pages.dev |
| work.yang181969.com | work-an5.pages.dev |

三条记录均启用 Cloudflare 代理，网站流量通过 Cloudflare 网络处理。

与迁移前相比，DNS 结构更加精简，也为今后添加新子域名提供了统一的管理入口。

### 5. WWW 永久重定向

在 Cloudflare Redirect Rules 中新增 301 永久重定向规则，将所有通过 `www.yang181969.com` 发起的访问统一重定向至 `yang181969.com`。

重定向保留原有页面路径与查询参数，避免不同域名同时提供相同内容，使网站拥有统一的正式访问地址。

### 6. 清理旧 GitHub Pages 配置

完成 Cloudflare Pages 部署后，移除两个 GitHub 仓库原有的自定义域名绑定，并停止使用旧的 GitHub Pages 网站发布方式。

保留 GitHub 仓库作为代码管理与版本控制平台，继续通过 GitHub 与 Cloudflare 的集成实现自动部署。

迁移期间曾短暂出现 GitHub Pages 404 页面。检查发现，Cloudflare 的 DNS 配置已正确生效，但本地网络仍存在旧解析缓存。刷新 DNS 缓存后，主站与子站均恢复正常访问。

至此，两个网站的 DNS 解析、托管服务与自定义域名迁移全部完成。

## 四、网站架构调整

本次迁移后，网站的基础设施正式调整为：

- **阿里云**：域名注册与续费管理。
- **GitHub**：网站源码保存、版本控制与代码更新。
- **Cloudflare DNS**：域名解析与统一管理。
- **Cloudflare Pages**：静态网站托管、自动部署与 HTTPS。
- **Cloudflare CDN**：全球内容分发、缓存及相关安全服务。

新的工作流程为：

`本地开发 → GitHub 提交 → Cloudflare 自动部署 → 网站更新`

这一架构减少了网站发布过程中的手动操作，使主站与独立子站能够分别维护、独立部署，同时保留现有的 GitHub 开发习惯。

## 五、总结与后续计划

2026 年 10 月 12 日的更新同时涉及网站功能精简、主页布局调整与底层托管架构迁移。

留言系统的退役标志着网站进一步减少非核心功能，将维护精力集中于内容创作；Cloudflare 迁移则完成了网站基础设施的一次重要调整，为后续长期运行和功能扩展提供支持。

接下来，网站将进入新一轮结构重构阶段：

- 将动漫、画廊及个人介绍等内容整合至 Life 页面。
- 逐步加入生活日记、个人里程碑等记录。
- 将 About 页面定位为网站介绍与站点信息中心。
- 优化 Notes 页面，为未来的交互式数学工具、物理模拟与科普内容预留扩展空间。
- 最终将主要导航精简为 Home、Life、Notes、About 四个板块。

本次更新不只是一次功能删除和服务器迁移，也是网站从早期功能积累逐渐转向结构清晰、内容优先、易于维护的个人知识库的一次阶段性调整。
