# 主页大改:从静态欢迎页到 Bento 仪表盘
@category: 建站日志
@date: 2026-05-01
@meta: 主页重构

劳动节这三天没出门,把拖了很久的主页改造一口气做完了。

旧主页一直是我心里的一个疙瘩——打开网站看到的是三张写着「关于这个网页」「你可以看到什么」「欢迎交流」的静态卡片,内容介绍了个寂寞,真正想看的笔记、动漫、画廊全得点进侧栏才能发现。访客第一眼只能读说明书,这个体验很糟。

所以这次彻底重构,把主页从「介绍页」改成了一个 **仪表盘** ——所有内容入口直接平铺在首屏,再把天气、统计、计时器、音乐这些日常会用到的小工具一起整理进来,组织成 bento 风格的布局。

## 左侧:常驻 220px 侧栏

侧栏从原来的「可折叠隐藏」改成了 **始终显示**,固定 220px 宽。除了 6 个导航项(主页 / 笔记 / 动漫 / 画廊 / 留言 / 关于),还集成了三个小工具:

- **月历** —— 简单的当月视图,不参与功能,纯粹是个看着舒服的存在
- **专注计时** —— 秒表 / 计时两个 tab,localStorage 累计,到点弹模态框提醒
- **音乐播放器** —— 顺序 / 随机 / 单曲循环三模式,带歌词切换

最满意的细节是音乐播放器的实现:它的 `<audio>` 元素挂在 `index.html` 自身上,跨页面切换时不会断。以前点笔记、点动漫,音乐就停了,体验非常碎。现在不管在哪个页面,左下角那首歌都在静静放着。

## 主区:12 列 bento 网格

主区是一个 12 列栅格,排了 9 张卡片,分三排:

**第一排 —— 信息密度最高的一排,横跨满宽:**

- 关于这个网页(span 6)—— 把原来三张介绍卡的精华浓缩成一张
- 今日心情(span 3)—— 挂 Open-Meteo 天气 API,坐标硬编码东京,30 分钟缓存
- 站点统计(span 3)—— 笔记 / 追番 / 留言 / 建站天数,一眼看完全站规模

**第二排 —— 三个内容入口平分宽度:**

- 笔记更新(最近 4 条:标题 + 学科 + 日期)
- 动漫追番(最近三部封面,新番带 NEW 角标,7 天阈值)
- 画廊更新(最近 4 张缩略图)

**第三排 —— 辅助信息:**

- 更新公告(最近几条摘要)
- 留言板(最新留言预览)
- 关于我(简介 + 头像)

每张卡片右上角都有个箭头直接跳到对应页面。这样首页本身就是一份「站点导览」,不用再读说明书。

## 数据层:两级缓存

九张卡片背后是九个数据源,频率和 API 性质都不一样。每次进主页都重新拉一遍既慢又浪费,所以写了 `js/home-cards.js` 做统一的数据获取层,带 **两级缓存**:

1. **内存级 Map** —— 同一 tab 内不重复请求
2. **localStorage**(`y181_` 前缀)—— 跨 tab、跨刷新仍然有效,各源单独 TTL

数据源混合多种:静态 JSON 索引(笔记 / 动漫 / 画廊)、Waline API(留言)、Open-Meteo(天气),还有几个直接读页面里的同步对象。表面是九张卡片,底下其实是一套小型的数据调度。

## 三天的节奏

- **Day 1** —— 侧栏从「可折叠」改成「常驻」,定下 220px,迁移导航
- **Day 2** —— 搭 12 列 bento 栅格,九张卡片的骨架和静态样式
- **Day 3** —— 写 `home-cards.js`,接上九个数据源,调缓存,处理边缘情况(空数据、加载失败、weather API 超时)

最磨人的是第三天。前两天的视觉部分做完很有成就感,新主页一下子就「亮」起来了。但把数据真的接通、处理各种「拉不到怎么办」「过期了显示什么」「第一次进来没缓存的体感」,反复调了一下午才稳。

## 写在最后

旧主页是给「访客」看的——一份正经的自我介绍。新主页更像是给 **自己** 用的——天气、计时器、音乐、最近发生的事,打开就在眼前。

某种程度上这也意味着这个网站对我的性质变了。它不再只是一个对外的「展示页」,而是我每天会真的回来看一眼的地方。劳动节做完这个改造,有种把一间房子真正住进去的感觉。
